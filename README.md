# 算法社团训练台

**A-Algorithm-Club-Training-Platform**

## RBC Helper 商品配置与 App 卡密验证

商城核销类商品新增“内部 Pro 卡密”来源，可配置 RBC Helper 和订阅天数（默认 31 天）。购买保存时长快照，背包领取卡密；旧商品、价格、库存和用户数据不自动修改。

App 通过 HTTPS 调用 `POST /api/app/cards/verify`，发送 `{"code":"RBC-..."}`，返回 `{"valid":true,"app":"rbc_helper","duration_days":31}`。首次有效验证返回订阅天数和激活回执凭据，先占用卡密 30 秒；App 激活完成后回执确认，才将卡密作废。占用期间重复验证返回占用错误，超时未确认则释放；不绑定设备、不生成登录凭据、不管理或累计订阅到期时间；App 自行处理激活与计时。

部署执行 `python manage.py migrate`（新增 `0053_app_pro_codes`、`0054_card_consumed`、`0055_card_activation_receipt`），更新 Web 和商城静态资源，保留原加密密钥，正确配置 HTTPS 和 `APP_TRUSTED_PROXY_CIDRS`。商品与库存须由管理员配置。请求字段、响应、错误码及调用示例见 [App 卡密验证 API 说明](docs/app-pro.md)。

This project was born out of the need to make it easier to compile statistics on members’ training records and to encourage club members to train themselves.

这是一个 Django + PostgreSQL + Celery 的团队训练平台，提供团队、学期、周次、即时计分、团队提交、点赞举报、排行榜、成员历史、RBC 商店和 Excel 导出接口。前端支持独立板块主题、深浅色外观和训练进展分析。

## 本地启动

1. 安装 Docker Desktop，并确保代理可以拉取 Docker Hub 镜像。
2. 复制 `.env.example` 为 `.env`，替换密钥和数据库密码。本地使用 HTTP 时设置 `DJANGO_SECURE_COOKIES=0`、`DJANGO_SECURE_SSL_REDIRECT=0`、`DJANGO_HSTS_SECONDS=0`；正式部署保留 HTTPS 配置。
3. Windows 推荐运行 `powershell -ExecutionPolicy Bypass -File deploy/start.ps1`。脚本会自动使用稳定的传统构建器。
4. 访问 `http://localhost/`。
5. 首次迁移会创建唯一管理员 `admin / admin123`；正式部署前修改默认密码，不再创建第二个超级管理员。

## 账号与权限

全站仅有一个管理员，初始账号 `admin`、密码 `admin123`。所有用户登录后进入同一主界面；系统管理员和团队管理员在左下角使用“管理工作台”。旧 `/manage.html` 地址会跳转到主界面内的工作台。
管理员可以创建/删除团队、设立/取消团队管理用户、管理所有配置项，并拥有所有团队的审核与驳回权限。
管理员查看团队无需加入，也不会占用成员数、影响排行榜。

普通用户自行注册账号，再通过团队码加入团队。注册和加入始终为“普通用户组”。

入队请求取得账号锁后再次核验活动状态和注销标记；即使请求在注销前已经通过登录验证，只要注销先完成，也会返回 403，不会创建新的活跃团队身份。默认昵称从锁定后的当前账号资料生成。
在主页“成员列表”管理当前团队成员：系统管理员可踢出用户、设置或取消团队管理；团队管理员只能踢出普通用户。系统管理员可切换任意团队。
管理用户归属“团队管理用户组”，只能审核所管理团队的举报，并可在该团队题目详情的“点赞”“举报”旁直接“驳回”提交。
取消某团队权限后保留普通成员身份；若仍管理其他团队，则保留管理用户组，但不能管理已取消权限的团队。

管理员邀请码与团队创建者自动升级机制已删除。普通用户和团队管理用户均不能创建/删除团队或修改全站配置。
全站唯一管理员不能被删除或降级；默认密码只在初始化/本次迁移设置，重启不会重置后续修改的密码。

### 前端工作台栏目

- 团队管理员工作台：举报处理、当前管理团队关联题目的待处理题名（补填题名、选择模式重新解析）。
- 系统管理员工作台：解析与API配置、全站题名待处理（无待办隐藏）、全站举报，以及创建/删除团队和团队计分配置。
- 两类管理员的工作台均不再显示团队成员管理。成员卡片的“踢出用户”“设置/取消团队管理”位于“查看历史提交”左侧；普通用户看不到这些操作。踢出仅停用成员资格，保留历史材料与统计。
- 所有日常配置均在主界面的前端工作台保存，无需进入Django管理后台。API Key仅显示保存状态，留空保留原值。

## 个人信息与算法平台绑定

团队管理员和普通成员点击右上角头像／昵称进入个人信息页。页面从右侧滑入，左上角 `<` 返回时向右滑出，并保留原来的主页面；支持键盘返回、浏览器后退和减少动态效果设置。

昵称仅修改当前团队的展示名，不修改登录账号；同团队昵称不可重复。头像和平台绑定按账号保存，在不同团队间共享。头像支持 PNG、JPEG、WebP（最多 3 MB、1600 万像素），保存为 256×256 JPEG，通过登录后的专属接口读取。

支持 Codeforces、AtCoder、牛客、洛谷、LeetCode、QOJ，每个平台可添加多个账号。牛客填写数字 UID，洛谷填写 UID 或用户名；LeetCode 中国站填写 `cn:用户名`。

账号卡片提供保存、同步、完整同步和解绑，支持全部账号同步。CF 可选填 API Key／Secret，牛客、力扣可选填 Cookie，QOJ 填写 Cookie；AtCoder 和洛谷只需账号。凭据加密保存，留空保留，勾选清除后移除。
LeetCode 账号填写 `cn:ID` 时同步中国站，填写普通 `ID` 时同步海外站；Cookie 必须属于对应站点及账号。填写 Cookie 后分页读取本人的提交历史，不填写时仅获取公开的近期 AC 记录；中国站与海外站分别适配题目字段。

首次同步读取历史题目，后续同步增量更新。同平台多账号的过题按题目合并去重，Rating 排行榜使用最高的当前 Rating。过题榜、热力图及补题 Tracker 使用同一份题目记录。

赛事中心的“补题 Tracker”提供 ICPC/CCPC、CF、AtCoder、牛客比赛题目矩阵。使用搜索和账号筛选；ICPC/CCPC 另有全部、ICPC、CCPC、省赛分类。点击题号打开原题，已 AC 题目标绿。

管理员在团队货币配置中统一设置签到、连签，并沿用小登／老登划分配置各平台赛内及补题奖励。QOJ 默认每题 2 Coins，可在个人空间或补题 Tracker 领取。

升级执行迁移 `0041`–`0044`，重新构建并重启 Web、Worker、Beat。`0044_merge_tracker_notifications` 仅合并 Tracker 与通知功能的迁移依赖，不修改业务数据。目录每天北京时间 06:00、18:00 更新。参考 [OJ Insight MIT License](docs/third-party/OJ-Insight-LICENSE.txt)。

## 题目展示与举报

提交必须填写题目链接并上传通过截图，写题逻辑和在线 Markdown Blog 可选。提交即计分并向当前团队成员展示。

题解思路为空、纯空白或仅为界面占位“未提交题解思路。”时，视为未提交，不计题解分；占位提示只在查看窗口展示，不写入编辑草稿。本人编辑、管理编辑、材料审核和同题递补均遵守此规则。迁移 `0052_correct_empty_logic_scores` 清理历史占位内容及误加分，修正受影响成员的积分和达标周数，保留历史昵称快照、提交次数、真实材料、签到和 Coins 流水，并记录积分修正审计；重复记录缓存中的占位分数也同步归零。
展示列表默认本周，可切换历史周；点击某题会显示该团队该题所有仍保留的历史提交，包含其他周和学期。
题解与 Blog 正文完整展示，支持公式、代码块和图片。Blog 由在线编辑器填写，不再提交站外 Blog 链接。展示以 Blog 为主体，通过截图使用可放大的缩略图，宽度足够时采用三列瀑布流。

每人每条提交最多点赞一次，可取消，不能点赞或举报自己的提交。举报时可选择常见理由或填写说明（最多 500 字），处理前材料继续展示。本人可取消待处理举报；已处理举报不可取消。取消后重新举报会建立新的通知批次。
团队“举报工作台”可驳回举报，或填写原因整条退回；管理用户也可直接在提交展示中驳回提交；退回后积分及有效次数撤销。
作者仅可在原提交周截止前修改重交，重交清空点赞、生成新版本并保留旧举报历史。
管理员不可处理自己的被举报记录；归档学期不可修改。

## 每日记录、个人维护与浏览

首页日期条可横向拖动，显示上周一至今天（共8至14天），松开后将最左侧显现的日期左对齐。今日可重复提交训练记录。历史未签到节点点击“补交当日记录”后先消耗一张补签券，开放一次提交权限，再弹出与今日一致的记录提交窗口。关闭窗口或提交失败时保留权限，再次打开不重复扣券，可在学期内跨周补交（仅保留可见节点入口，已移出显示范围的日期不另设入口）；提交成功才创建补签签到记录、计入训练积分，并重新核算所在自然周连签奖励。成功后的按钮显示“当日已补签”并禁用；重复请求、删除记录均不会恢复该次权限。无券时弹窗引导前往 RBC 商店，已持有的下架券仍可使用。学期结束或归档后不能继续补交。数据库迁移：0024_makeup_submission_permission。

“我的提交”的查看窗口有专属编辑、删除标签，提交展示和成员历史查看不提供这些个人操作。编辑保留原归属日期，未换截图时复用原截图，更新版本、清空旧点赞并重新计分；编辑和重交受原周截止限制。删除整条记录会同步撤销积分、有效次数和达标统计，附件进入持久清理清单。

排行榜点击成员可打开成员历史。二级窗口提供返回上级按钮，Markdown 编辑器保持其原有独立操作。提交表单下方有力扣每日一题（接口获取当日链接）与牛客每日一题入口。

## 全站题名解析

系统管理员登录主界面后，点击左下角“管理工作台”，在“题目解析与 API 配置”栏选择：

- 自动解析：读取公开网页题名；优先适配牛客、洛谷、LeetCode、Codeforces、AtCoder。
- AI解析：仅发送网址和固定 Prompt，要求配置的服务具有联网读取能力。
- 智能解析（默认）：自动解析失败后调用AI。

AI配置填写 API Base URL（例如 `https://api.example.com/v1`）、API Key 和 Model。
调用协议可选 `Chat Completions` 或 `Responses（启用联网搜索）`：前者使用 `POST /chat/completions` 和 `choices[0].message.content`；后者使用 `POST /responses`，显式携带 `web_search` 工具并读取 `output_text`。两者均使用 Bearer 鉴权。CPA/Codex 服务经实测可通过 Responses 执行联网取名；支持范围仍取决于所配置上游。
Key加密保存；留空保留原值，页面只显示掩码。加密密钥派生自 `DJANGO_SECRET_KEY`，更换该密钥后需重新填写API Key。
在前端保存配置后，点击“测试已保存的 AI 配置”。测试会发送牛客示例题目网址，可能产生一次API调用费用；连接成功但模型返回空题名时，会单独提示未能确认题名。

题名解析通过 Celery 执行，不阻塞提交。已记录的题目不会因重复提交、切换模式或修改配置而重复请求。
未取得题名时显示网址。前端工作台的“待处理题目名称”栏展示失败或处理中的题目，可直接补填题名或选择模式重新解析；系统管理员处理全站题目，团队管理员只处理当前管理团队提交关联的题目。没有待处理项时整栏隐藏。
人工修改会阻止迟到任务覆盖；重试失败不会清除已有题名。待处理队列支持删除命名任务：保留题目与提交记录，并取消旧任务写回；没有题名时继续显示原题链接。

## 正式部署

将项目上传到 Debian 12 服务器，配置 `.env` 中的域名和密码，开放 80/443 端口后运行 Docker Compose。Nginx 负责反向代理和媒体文件，PostgreSQL、Redis、Celery Worker/Beat 由 Compose 管理。

生产环境 `.env` 至少需要设置：

```dotenv
DJANGO_ALLOWED_HOSTS=redbloodcell.cn,www.redbloodcell.cn
DJANGO_CSRF_TRUSTED_ORIGINS=https://redbloodcell.cn,https://www.redbloodcell.cn
DJANGO_SECURE_COOKIES=1
DJANGO_SECURE_SSL_REDIRECT=1
DJANGO_HSTS_SECONDS=31536000
```

如果前面使用 Cloudflare，请将 SSL 模式设为 Full (strict)，并确保 Cloudflare 的 `X-Forwarded-Proto` 被 Nginx 转发给 Django。

更新前端或后端后，需要重新构建 Web、Worker、Beat 镜像并重启 Compose 服务；只替换浏览器里的 HTML 不会更新服务器数据库接口。

HTTPS 证书可以用 Certbot 写入 `deploy/certbot/conf`，证书更新后重新加载 Nginx。

## 升级注意

**迁移 `0010_account_roles` 会一次性清空所有旧账号、成员关联、训练记录、积分、审核日志及登录会话，仅保留唯一管理员 `admin / admin123`。**
现有团队、学期、周次、题名缓存与AI配置保留，团队归属转移给管理员；原管理员邀请码不再使用。
该清理不可回滚，仅执行一次。此后新注册用户和重新分配的管理权限在重启后保留。


**迁移 `0008_community_library` 会在所有升级环境一次性删除全部历史提交、材料、审核日志、积分汇总和擂台数据。**
账号、团队、成员、学期、周次和计分配置保留，历史积分及达标次数归零。该数据清空不可回滚。
先停止 Worker / Beat，再构建新版 Web 并运行迁移和 collectstatic，最后恢复 Worker / Beat 并重新启动 Nginx。
Web 启动命令已包含迁移和 collectstatic；本地启动脚本使用项目名 `club-platform`。

迁移将待删除文件写入 FileDeletion 清单，由每分钟后台任务分批删除；失败保留并重试。
可在站点后台检查清理清单，或运行 `docker compose -p club-platform exec web python manage.py shell -c "from club.tasks import purge_files; purge_files()"` 立即尝试清理。
后续普通重启不会删除新记录。

周次按上海时区每周一00:00切换，截止后禁止提交或重交；周次日期异常仍需通过 `repair_weeks` 人工检查修复。
清理改为管理员在“团队配置”中设置具体北京时间，实际执行时间为所选时间加7天。设置后显示剩余天数，可在实际执行前撤销并重设；未设置不自动清理。清理提交、截图、写题逻辑、Blog、点赞举报及审核明细，保留账号、团队、学期周次、学期汇总和全站题名缓存。附件只通过受权限保护的 `/api/attachments/<id>` 提供。

迁移 `0014_manual_cleanup_schedule` 会取消未归档学期的旧自动清理计划，不删除这些学期的提交。管理员须重新设置清理时间；已归档学期失败的文件清理仍可重试。

## 回归测试

使用独立 PostgreSQL 测试数据库运行 `python manage.py test club`，不要使用生产数据库账号。
测试覆盖新展示、即时计分、举报退回、截止、题名模式与缓存、API模拟、并发、权限、迁移清空和文件清理重试。
实际AI联网能力需配置真实API后单独验证；模拟API测试不代表外部服务可联网。

个人比赛进度、AC 领奖、年级自动晋升和自然周连签奖励见 [赛事中心说明](docs/contest-calendar.md)。升级需运行迁移 0017–0019 并同步重启 Web、Worker、Beat。

个人信息支持验证旧密码后修改密码；注册选择入学年份，年级和分队自动计算。提交展示支持对同团队其他成员的有效未归档提交打赏正整数 RBC Coins：双方余额与流水在同一事务更新，同一请求重试不重复扣款。升级需迁移 `0022_submission_tips`。

打赏流水通过原打赏记录显示对方的当前团队昵称及准确的 Coins 金额，例如“收到 小明 对提交 #123 的打赏，+7”。对方改名后显示新昵称，注销后统一显示“已注销用户”，不显示旧昵称。存储的说明只保留收支类型和提交编号，迁移 `0050_anonymize_tip_descriptions` 清理旧昵称快照；`0051_link_tip_ledgers` 为流水增加打赏记录关联，并仅为可唯一确认的历史流水补关联，无法可靠匹配的记录只显示收支及金额、不猜身份。迁移不改金额、余额或原打赏凭证，每笔打赏的同一收支方向至多一条关联流水。

### 拓展资源墙

菜单“拓展”为全站共享资源墙，每个资源占一个正方形格子。系统管理员可在该页添加、编辑、删除资源，配置名称、简介、可选封面，以及 HTTP/HTTPS 超链接或下载文件。普通成员和团队管理员仅可浏览、下载。文件与封面不设上传大小上限，封面支持 PNG/JPEG/WebP，封面会转换为正方形 JPEG。文件通过登录与成员权限校验后以附件下载，删除或替换的文件进入现有文件清理队列。数据库迁移：0023_extension_resources。

赛事中心由 Celery Beat 每日北京时间06:00、18:00触发后台更新，五个平台的数据及更新时间保存在数据库。打开日程只读取已有快照，不等待平台请求；更新失败保留最近成功数据。手动“刷新日程”沿用原缓存逻辑：成功15分钟内复用，失败60秒后可重试。新部署后可调用 `club.tasks.refresh_contest_calendar.delay()` 异步初始化，之后由定时任务维护。迁移：0025_persisted_contest_calendar。

## 外观、训练分析与提交界面

设置提供带名称的柔和主题色、深浅色板、板块独立颜色与字号、圆角和动画控制。外观保存在当前浏览器，切色采用实心覆盖后圆形揭示的两段动画，并尊重减少动态效果偏好。训练总览包含固定周一至周日的日期栏、积分与提交进度、可切换统计口径的热力图，支持近四个月或按管理员设置的学期日期展示；历史日期可从热力图进入。

## 核销商品 API 请求格式

商品设置支持库存卡密、API 卡密和实物派发，现有补签券等商品保留原有行为。库存卡密每行追加一条：购买时预留，背包核销时消耗。API 卡密购买后不会立即请求接口，用户在背包点击核销时才发起请求。实物购买后显示“派发中”，工作台生成待派发记录，管理员人工发放并确认后显示“派送成功”。

管理员填写的 API 配置是 JSON 对象，例如：

```json
{
  "url": "https://cards.example.com/issue",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer YOUR_TOKEN"
  },
  "body": {
    "product_id": "example-product"
  },
  "response_path": "data.code"
}
```

- `url`：公开的 HTTPS 地址；不允许本机或内网地址，不跟随重定向。
- `method`：`GET` 或 `POST`，省略时为 `POST`。GET 不发送请求体；POST 将 `body` 序列化为 JSON。
- `headers`：字符串键值对象，可放接口鉴权信息。服务端固定发送 `Content-Type: application/json` 和 `Idempotency-Key`，同名配置不能覆盖这两个值。
- `body`：JSON 对象，内容原样发送，不替换成员信息或其他模板变量。
- `response_path`：响应 JSON 中的卡密字段，默认 `code`；支持 `data.code` 及数组数字索引。

以上配置会产生如下 POST 请求：

```http
POST /issue HTTP/1.1
Host: cards.example.com
Authorization: Bearer YOUR_TOKEN
Content-Type: application/json
Idempotency-Key: <该背包物品的固定 UUID>

{"product_id":"example-product"}
```

接口应返回 HTTP 200 和 JSON，例如：

```json
{"data":{"code":"EXAMPLE-CARD-CODE"}}
```

卡密必须是非空字符串，最多 4096 字符；响应体最多 1MB，请求超时为 8 秒。接口必须支持 `Idempotency-Key`：同一物品的重复请求返回同一发卡结果，以处理接口已发卡但响应超时的情况。平台在请求失败、响应格式错误或卡密字段缺失时不消耗物品；核销成功后保存结果，重复点击和再次查看不会重新请求 API。

API 配置和卡密在数据库中加密保存，商品公开列表不返回秘密配置；已核销卡密仅购买者可读取。已有配置在编辑时留空保留。完整操作与上线注意事项见 [商品核销与派发](docs/shop-fulfillment.md)。

## 全局账号与团队身份维护

登录账号、密码、头像和平台绑定属于全局账号；团队展示名、管理身份及积分属于各个团队；Coins 余额、流水和背包属于全局账号，在不同团队之间互通。修改全局登录账号或密码不会修改团队展示名，也不会合并不同团队的数据。

全局 Coins 允许因系统管理员调整、举报扣款或已付奖励收回产生负余额。管理员的全局账号、成员资料及快捷增减入口均支持该规则，普通消费和打赏仍必须余额足够，不能透支。后续签到、比赛、举报奖励、收到打赏及物品回收退款直接增加当前余额，优先抵扣欠额。删除/驳回引发奖励收回时，继续先按原规则预览并确认回收符合条件的未使用物品；不足部分记负余额，不追收已使用或已交付物品。举报确认会计入额外扣款并提示负余额。余额范围为 -2147483648 至 2147483647；迁移 `0049_currency_transaction_big_amount` 将流水变动金额扩为 64 位，支持正负余额极值之间的完整审计。

系统管理员工作台的“全局账号”列出所有账号（包括未加入团队的账号），支持搜索、修改登录账号、重设密码及注销。团队管理员无权管理全局账号。普通用户可从个人信息或团队选择页注销自己；注销必须填写当前密码并输入“注销账号”。系统管理员注销其他账号时需提供管理员密码并核对目标登录账号，系统管理员自身不可注销。

注销采用停用和匿名化：退出所有团队身份、清除头像及平台绑定凭据、禁止继续登录，保留匿名的已发布提交和交易记录以维持团队历史与账目。注销不同于退出某个团队。请在部署前备份数据库和媒体文件，再执行迁移 `0045_account_closure_report_reasons`。

注销同时匿名化所有团队的学期汇总昵称快照（包含已归档学期），历史查询和 XLSX 导出不再保留原昵称；积分、有效提交次数和达标周数不变。写入顺序为账号、相关学期、团队身份，避免与统计重算相互覆盖。

个人资料修改在获取账号锁后重新核验账号未停用、未注销且当前团队身份仍有效；注销前已发起、但注销后才取得锁的请求返回 403，不会恢复旧昵称或头像。成功响应也在该锁内构建，避免保存与响应之间成员失效导致错误。

新增、修改、删除及同步平台账号和旧平台绑定入口共用相同的锁内状态核验，注销后不能保存凭据或重建绑定。比赛历史保留每条参赛记录及过题凭证，以独立的匿名标识替换账号，并清空原始资料和同步错误快照；同一平台、同一比赛下的多个账号记录不会因匿名化产生唯一键冲突，本人及管理员注销均适用。

注销在同一账号锁内作废比赛同步令牌，将同步状态标为取消并清空进度消息。比赛发现、最终同步状态更新及详情补全均按“账号 → 同步状态 → 历史记录”的顺序加锁，锁内复查账号和令牌；远程请求不持有这些锁。注销先完成时丢弃迟到结果；写事务已开始时注销等待其提交，再一并匿名化新记录。旧任务和注销前发起的同步请求不能恢复原账号、原始资料、错误快照或待同步状态，已有过题/领奖凭证保留。

接口：`GET /api/account` 返回当前全局账号；`GET /api/management/accounts?q=&page=1` 每页 20 条；`PATCH /api/management/accounts/<id>` 接收 `account` 和可选 `password`。本人注销 `POST /api/account/close` 接收 `confirmation: "注销账号"` 和 `password`；管理员注销 `POST /api/management/accounts/<id>/close` 接收相同确认文字、目标 `account` 和 `admin_password`。所有写入接口需要登录及 CSRF 验证。

举报 `POST /api/submissions/<id>/report` 接收 `{"reason":"说明"}`；`DELETE` 同一地址只取消本人的待处理举报。为兼容旧客户端，缺失 reason 字段时记录为旧版未填写；显式空白理由会被拒绝。理由仅向有权限的举报处理工作台展示，不公开在团队题解列表中。

撤销举报或注销举报者时，按通知数据中的 `payload.data.report_id` 取消对应的待发送 AstrBot 通知；不影响已送达通知或其他举报者的通知。重新举报使用新的代次通知，只发送重新填写的理由。

举报队列的 `report_details` 包含每条举报的 `id` 和 `generation`。处理举报的 `POST /api/admin/reports/<id>/resolve` 必须携带完整 `report_snapshot: [{"id":123,"generation":1}, ...]`，缺失快照、仅有旧 `report_ids`、举报增删或撤销后重新举报均返回 409，重新查看当前理由后才能处理或结算 Coins。直接驳回当前版本提交的接口不需要举报快照。升级后旧页面需刷新以加载新的快照提交逻辑。


## 全局资产、账号窗口与题解管理

迁移 `0046_global_wallet_and_worn_titles` 会按账号汇总已有团队余额（求和，不重复发奖），保留原余额来源，并将历史流水关联到全局账号。积分和训练统计继续按团队计算。背包展示账号在所有团队获取的物品；卡密、实物及消耗品保留原始购买团队和履约状态。补签券可用于当前团队的补交规则，使用时仍需核验日期与本学期权限。踢出团队只停用该团队身份，不注销账号、不清空全局 Coins 或背包。迁移后的全局余额无法自动拆回原来的团队余额，回滚需恢复部署前数据库备份。

管理员“全局账号管理”提供搜索列表与资料编辑窗口，列明所有团队身份，未入队账号也可管理登录资料和 Coins。团队成员窗口提供“踢出当前团队”和“注销全局账号”，两者影响不同。`GET/PATCH /api/management/accounts/<id>` 支持全局资料和 `action: "balance"`（需携带 `expected_balance`）；`POST /api/management/accounts/<id>/inventory` 支持发放、调整数量及收回未使用物品。背包修改会核对实际所有者，卡密内容不会返回到管理列表。

管理员可通过 `GET/PATCH /api/management/submissions/<id>` 编辑有权管理的团队题解。修改提交 `version`、`logic`、`code`、`code_language` 和 `blog`；保留原作者、日期及截图，重新计算内容积分，写入管理员操作记录。已归档学期不可编辑，已退回的提交不会因管理编辑自动恢复为有效或重新领取奖励。旧版本待处理举报注明“管理员已修改题解”，新版本需重新核验。

管理编辑入口仅能编辑其他账号的提交，不能借修改自己的题解关闭自己的待处理举报。本人提交仍走普通编辑入口并遵守截止、归档等限制；展示页不会为作者显示管理编辑按钮。

举报工作台按同一提交、同一版本合并为一项，窗口列出各条理由和时间。处理时必须携带包含编号和代次的 `report_snapshot`；如果有人新增、取消或重新举报，服务端返回 409，界面刷新后再确认，避免处理尚未看过的新举报。举报理由输入框只允许纵向调整，窗口高度受视口限制，内容在窗口内部滚动。

称号继续按团队授予，新增安全枚举样式 `plain/chroma/wings/captain/president/deputy`，分别用于简约、炫彩、羽翼和不同身份徽章。样式不赋予任何管理权限。个人信息可选择佩戴一个已授予称号或不佩戴，`POST /api/profile/titles/wear` 接收 `{"title":"称号文字"}` 或 `{"title":null}`；榜单和个人名片只展示佩戴的称号。旧资料首次选择前保留已有展示。


## 举报成立时的 Coins 奖惩

举报处理窗口默认每位选中的有效举报者奖励 1 Coins、被举报者整条提交额外扣除 1 Coins；原提交相关奖励仍按原规则撤回。管理员可在每次处理时分别设置 0–100 的整数金额（0 表示不调整），并选择哪些举报者获得奖励；同一个账号重复出现只奖励一次，多位举报者不增加被举报者的扣款次数。取消、已处理或账号已停用的举报者不进入有效奖励名单。驳回举报、直接退回及管理员编辑题解不触发此奖惩。

确认举报成立时，`POST /api/admin/reports/<id>/resolve` 携带 `action: "reject"`、`version`、`note`、完整的 `report_snapshot`（编号与代次），以及 `report_coins: {"reward_each":1,"author_penalty":1,"reporter_ids":[账号ID,...]}`。旧客户端不提交此设置时保持不加扣。处理和奖惩在同一事务完成，记录全局 Coins 流水及管理员审核日志；同一版本重复处理不能重复发奖。被举报者余额不足时允许产生负数，窗口会明确提示。部署需执行迁移 `0047_report_coin_transaction_types`，不修改已有余额。


举报 Coins 的金额和获奖名单移至举报处理窗口的“奖励设置”独立窗口；“返回举报处理”、关闭按钮或 Esc 返回时保留本次合法输入，返回不会提交审核或实际加扣。确认举报成立后才执行奖惩。服务器兼容合并与更新步骤见 [本次服务器更新注意事项](deploy/UPDATE_NOTES.zh-CN.md)。

### 德州扑克

仅在「拓展」页面点击「德州扑克」进入房间大厅。游戏在拓展页内部打开，可通过「返回拓展」回到资源卡片；刷新后先回到拓展页，再点入口即可恢复仍存在的座位。旧的 `/?view=poker` 链接会回到拓展页，不会直接打开游戏。

- 多人局：同团队成员可创建多个房间，每桌 2–9 人。团队需启用 RBC Coins；每个账号同时只能占一个座位。默认底注 1000 筹码，盲注 1 / 2，底注最低为大盲注。大厅按 1 Coin = 1000 筹码买入，创建或加入时扣除筹码底注，离桌返还剩余筹码。提现每满 1000 筹码兑换 1 Coin，余数保留；买入和提现写入钱包流水，无抽水。
- 多人练习：2–9 人免费联机，每人赠送 1,000 筹码，盲注 5 / 10。筹码用完可重新领取，退出后作废，不影响真实钱包或收入；无需团队启用货币。
- 人机练习：个人房间支持 1–5 个机器人，每人赠送 1,000 练习筹码。练习筹码用完可重新领取；不能兑换 RBC Coins，不计钱包收入、交易流水或财富排行。团队未启用货币时仍可练习。
- 规则：无限注德州扑克，支持盲注、四轮下注、全下、边池、平局分池及庄家轮转。所有在座且有筹码的玩家准备后开局；中途加入的玩家等待下一手。
- 桌面：玩家环绕椭圆牌桌，自己的座位固定显示在下方，公共牌与底池在桌面中央；手机端使用纵向牌桌。
- 连接与离桌：牌桌每 1.5 秒同步一次，状态持久化在 PostgreSQL，兼容现有多进程 Gunicorn。每次行动限时 45 秒，超时自动过牌或弃牌。断开页面 5 分钟后申请离桌；进行中的玩家本手结束后结算，全下玩家保留比牌资格。页面重新打开会恢复仍存在的座位。

部署时运行 `python manage.py migrate`，并保持现有 Celery worker / beat 启用。新增的 `sweep_poker_rooms` 每 15 秒处理超时与无人在线房间；在线房间的 API 同时推进超时和机器人动作。多人局底牌只返回给本人，摊牌时公开未弃牌玩家底牌。


API 类核销商品可开启“允许单次多购”（默认关闭）。开启后，商店卡片显示 1–100 件数量输入，受库存限制；按单价 × 数量扣款、扣库存，背包仅生成一份物品，显示卡密可用次数。核销时 POST JSON 请求体增加 `num` 整数（覆盖配置中同名值）；GET 则增加 `num` 查询参数（替换原同名参数）。数量在购买时保存，关闭开关不改变已购权益，重试沿用同一 Idempotency-Key。旧订单、未开启多购的卡密仍按原方式履约。回收未核销的多次数卡密时整份回收，退回原订单总价并恢复对应数量库存。升级需执行迁移 `0057_api_card_multiple_purchase`，重建 Web、Worker、Beat。

### 绑定账号自动同步

Celery Beat 每天北京时间 04:00 启动账号同步队列，每 30 秒检查一次，一次只启动一个账号；已有同步任务运行时等待。只同步仍有有效团队身份的活跃用户，跳过最近 12 小时同步成功的账号。同一天不会重复自动启动同一账号；队列跨日期后停止。需同时运行 Beat 和 Worker。

复用现有账号同步流程，已有完整历史的账号优先增量同步；尚未完成历史同步的账号可能需要补齐历史。过题明细内容没有变化时不重复写入。失败账号保留原数据并暂停自动同步，需要用户检查凭据后手动重试；超过 30 分钟无进展的任务标记为失败。手动同步入口及原有错误、进度、更新时间展示保持可用。

LeetCode 过题证明、归档和平台明细按当前绑定分区统一去重；双服同时绑定时同题只计一次，累计总数保底取较大值。历史记录在查询时归并，保留原始证据，不调用 AI API；详见 [LeetCode 历史数据处理方案](docs/leetcode-solved-history-reconciliation.md)。
