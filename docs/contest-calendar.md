# 赛事中心、平台账号与奖励

## 个人空间

每个平台可绑定多个账号，分别同步 Rating、过题数和题目记录。支持编辑、解绑、全部同步和重新完整同步。排行榜取最高的当前 Rating；同平台过题去重，首次 AC 日期取最早记录。力扣中国站使用 `cn:` 前缀，与国际站分别统计。

Codeforces 可填写 API Key / Secret；牛客和 LeetCode 可填写 Cookie；QOJ 使用用户名和 Cookie。凭据按账号加密保存，编辑时留空保留，支持替换和清除。洛谷使用公开账号或 UID，管理员查询 Cookie 继续用于逐题 AC 时间查询。

注册选择入学年份，年级由入学年份和当前学期计算，分队与称号沿用现有功能。奖励配置沿用小登／老登划分，分队只用于展示。

## 赛事日程与补题 Tracker

赛事日程提供 Codeforces、AtCoder、牛客、洛谷、LeetCode 的比赛快照；“已参加”展示历史参赛进度和领奖入口。

补题 Tracker 提供 ICPC/CCPC、Codeforces、AtCoder、牛客四类比赛矩阵。支持搜索、全部账号或单账号切换，ICPC/CCPC 增加全部、ICPC、CCPC、省赛分类。每页 20 场，点击题号打开原题，窄屏可横向滚动。

目录来源：QOJ 分类与比赛页、Codeforces 官方常规比赛 API、AtCoder Problems、牛客官方 Tracker。ICPC/CCPC 使用 XCPCIO 与 RankLand 公开榜单匹配金银铜铁分档。QOJ 登录后取得的题目详情按账号保存。

日程和 Tracker 目录每天北京时间 06:00、18:00 更新，页面也可刷新目录、同步账号。

## 管理员奖励配置

在“管理工作台 → 团队配置 → Coins 规则”中，统一设置全队的每日签到、自然周连签，并按小登／老登分别设置各平台赛内 AC 与补题 AC 金额。平台题目奖励分三档；QOJ 使用统一单题金额，赛内和补题默认每题 2 Coins。其他平台补题默认 0，赛内沿用既有金额。配置 0 关闭对应奖励。

| 平台 | 第二 / 第三档起点（大一上） | 第二 / 第三档起点（其余年级） |
|---|---:|---:|
| LeetCode | 600 / 1200 | 1000 / 1500 |
| Codeforces | 1000 / 1600 | 1400 / 2000 |
| AtCoder | 400 / 1000 | 800 / 1600 |
| 牛客 | 1100 / 1600 | 1600 / 2100 |
| 洛谷 | 2 / 4 | 4 / 6 |

签到与连签保持原来的全队统一金额。小登为入学后的第一个秋季学期（包含次年 1 月），2 月 15 日起转为老登；不以分队区分奖励。赛内按比赛开始日期、补题按首次 AC 日期判定奖励身份与难度阈值，AC 日期未知时按当前日期。赛内奖励沿用参赛与时间核验规则，奖励起点为北京时间 2026-11-01。补题使用已同步的具体题目 AC 记录；已取得日期的记录从该日起参与奖励。

个人空间和 Tracker 的补题领奖、比赛页领奖共用凭证；同团队同用户同平台同题、同平台账号同题均只发一次。发奖、余额和流水在同一事务中更新，解绑和重绑不会重置领奖凭证。

## 升级与接口

执行迁移 `0041`–`0044`，重新构建并重启 Web、Worker、Beat。`0044_merge_tracker_notifications` 仅合并 Tracker 与通知功能的迁移依赖，不修改业务数据。通知每分钟检查，Tracker 目录继续每日北京时间 06:00、18:00 刷新。迁移保留现有绑定、历史关联及领奖记录，后续同步补全题目记录。

- `POST /api/profile/platforms/{platform}/accounts`：添加账号。
- `PATCH/DELETE /api/profile/platform-accounts/{id}`：编辑、解绑。
- `POST /api/profile/platform-accounts/sync`：按账号 ID 列表同步，可指定完整同步。
- `GET /api/trackers/{kind}`：读取分页比赛矩阵。
- `POST /api/trackers/{kind}/refresh`：刷新目录。
- `POST /api/profile/platform-rewards/claim`：领取补题奖励。

旧平台绑定接口保留单账号兼容。多账号凭据使用现有系统密钥，升级时保留环境配置和密钥。

### 每日自动比赛检查

后台每天北京时间 04:00 启动比赛检查，按用户去重处理仍有有效团队身份的绑定账号，支持 Codeforces、AtCoder、牛客、洛谷和 LeetCode。QOJ 继续走普通过题流程。

自动任务只发现比赛和更新 AC 核验结果，不领取奖励、不修改余额。用户仍需在赛事中心手动领取。首次检查会补查奖励生效日期之后的比赛；后续重新核验近七天比赛及未完整核验的记录，已完整核验的更早比赛不反复抓取题目。比赛历史来源仍按各平台接口能力获取。

每五分钟执行一次恢复检查：04:00 之前不启动，当天已启动并完成的用户不重复调度；同一用户运行中的同步优先完成；不同用户最多同时保留三个比赛检查流程，避免单个账号阻塞其他用户。服务错过凌晨执行时间时，当天恢复后补跑；超过三十分钟没有进度的自动任务会重新调度。停止数天后恢复只启动当天一轮，不补建每天的重复任务。所有后台服务需要正常运行。

赛事中心显示最近自动检查日期及完成状态，平台失败信息仍保留在同步结果中。升级需应用 0068_contest_auto_check 迁移并重启 Web、Worker、Beat。


### 同步协调与平台限流

后台 Worker 使用两个执行进程。自动账号同步和比赛检查分别限制在最多三个待处理流程，同一类同步不会为正在执行的用户重复创建自动任务。比赛检查每次分发一个用户，并在三十秒后继续补充空闲名额；每五分钟的恢复检查保留。

账号同步暂时没有可分发账号、但仍有账号正在同步时，继续每三十秒检查；当前账号完成后，再处理同一用户剩余账号，直到本轮完成或跨日。

比赛任务另有排队期限：排队超过一小时，且整个同步流程连续三十分钟没有进展时，在锁内重新核对 token 和排队状态后结束本轮，释放名额。自动任务沿用每日最多三次及 5/10 分钟退避；手动任务可重新同步。该期限不用于认定 worker 死亡，仍在正常推进的流程不受影响。旧消息迟到时由 pending 状态和 token 校验阻止写回。

账号、比赛与 Tracker 适配器共用 Redis 原子请求门控：Codeforces 和 AtCoder（含提交镜像）间隔三秒，牛客、洛谷、LeetCode、QOJ 间隔两秒。平台别名域名共用额度，不同平台互不占用。等待不会超过任务请求期限，限流服务故障时不绕过限流直接请求。

连接故障、HTTP 429 和 5xx 使用有限重试；明确账号或 Cookie 不匹配、缺少凭据，以及 HTTP 401/403 等访问拒绝停止账号级自动重试，保留记录与游标并提示检查后手动重试。HTTP 403 也可能来自平台访问限制，不能据此认定 Cookie 一定失效。

自动比赛查询遇到外站发现或题目核验失败时，任务保留 failed 状态；部分成功的进度继续保留。外站失败每天最多尝试 3 次，前两次失败分别等待至少 5、10 分钟后由恢复检查重新调度。达到上限后仍可手动同步，次日重新计数。只有全部完成且无错误才记录自动完成时间。

同一日的首次入队失败、题目核验入队失败和自动任务中断，统一进入上述失败恢复流程，不清空 auto_checked_on 或重置 auto_attempts。中断恢复前在锁内重新检查任务 token、pending 状态和最近进展时间，避免旧回调或过期扫描覆盖已经完成、恢复或手动启动的新任务。

后台执行监控：ContestTaskRun 保存任务 ID、同步 token、排队/已接收/执行状态、worker 启动标识及心跳。执行心跳每 20 秒更新，worker 心跳由 Celery 定期刷新（90 秒租约）。每分钟恢复检查仅处理任务心跳超过 120 秒、且所属 worker 连续两次检查均缺失（至少间隔 60 秒）的已接收或执行中任务；Redis 不可用不视为 worker 死亡。单纯排队不触发执行超时。确认中断后仍沿用每日最多 3 次及 5/10 分钟退避策略，旧 token 不得写回。无监控记录的旧任务继续保留 30 分钟兜底。页面不增加展示。正常停止 worker 的宽限期设为 15 分钟，让执行中的任务有机会完成。
