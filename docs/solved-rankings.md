# 过题榜与奖励日期

总览和完整排行榜的过题榜均提供“学期榜 / 总榜”，默认学期榜。API 使用 `/api/leaderboard?scope=solved&period=semester`（默认）或 `period=all`。两种数据分开缓存，快速切换时不会相互覆盖。其他榜单、排序和并列名次规则不变。

总榜使用下述平台基线、后续比赛增量、本站有效且截图通过的提交及已归档凭证。学期榜按当前团队活动学期的自定义起止日期统计相同账号的去重题目，统计上限为今天；无活动学期时为零。本站提交使用归属日期；比赛和平台记录仅使用可确定的实际 AC 日期，转换为 Asia/Shanghai 日期；未知时间不以比赛开始日期或同步日期代替。日期边界均包含当天。题目按现有来源和题目标识去重，保持与总榜相同口径。

过题量不以 2026-11-01 截断，也不要求领取 Coins。新增带日期的持久凭证，使历史比赛、归档提交在清理后仍可计入对应日期范围。仍有效的本站提交直接计算，删除或驳回后失去依据的提交不保留学期过题凭证。演示数据、不通过题目和从未核验绑定的参赛账号不产生凭证。

迁移 `0037_dated_solved_credits` 分批从已有已绑定参赛账号的 AC 记录及仍有明细的已归档提交补入凭证，不请求外部平台、不发奖。只有累计凭证但已无任何原始日期依据的老数据保留在总榜，不用同步/创建时间伪造学期归属；重新同步平台历史后，可补齐仍可取得的比赛日期。

奖励门槛与统计独立：保留 `2026-11-01 00:00:00 Asia/Shanghai` 起的比赛及正式赛内 AC 门槛；已知 AC 时间早于该时间不得领奖，11 月 1 日当天计入允许范围。时间不可核验的可靠 AC 继续沿用原有宽松兜底，但其比赛也必须达到上述日期门槛。仍保留当前绑定、有效年级、奖励配置、官方时段和防重复领取检查。修改榜单范围不会修改 Coins 余额、已有领取凭证或奖励金额。

部署先备份数据库，应用迁移后更新静态资源即可。迁移不会恢复已被平台删除或未同步的历史记录；需要时在赛事中心同步现有绑定账号的完整历史。


## 一次平台基线与后续增量

首次绑定平台账号时，现有后台资料同步同时建立 PlatformSolvedBaseline：累计去重题数、可获取的题目标识、已知 AC 日期和抓取时间。Codeforces/牛客分页读取公开 AC 历史，AtCoder 使用 AtCoder Problems 总数与时间分页；LeetCode、洛谷保留可靠累计数，公开或授权查询可取得多少 AC 时间就记录多少，无法追溯的日期不伪造。失败记录不作为零基线，不会使用首屏/最近 1000 次提交冒充平台完整累计数。

成功基线不会在普通“同步资料”时重新抓取做题历史；更换绑定账号会清除旧基线并重新获取。获取失败可在个人资料页同步重试。所有写入受绑定账号和任务版本校验，旧任务不能覆盖新账号。

过题总数 = 各已绑定平台的基线总数之和（未知日期 + 已知日期）+ 本站有效/归档的去重题数 + 绑定之后赛事中心核验的新题增量。平台与本站提交按独立来源累计；同一来源内去重。基线中已有的比赛题目不重复累加；绑定前旧比赛只可补全基线日期。只有平台总数而无完整题目标识时，对绑定前已开始的比赛保守地不额外计入增量，避免重刷旧题虚增。

学期榜和热力图只使用上述数据中实际日期可确定的题目。热力图固定按过题数着色，原日常提交次数不再作为热力图数据源，但后台日常提交、签到、补交和积分逻辑保持独立。总览会提示还有多少日期未知的题目仅计总榜。Coins 奖励不读取基线，仍只由赛事中心原有资格与 2026-11-01 日期门槛判定。

现有绑定账号在部署迁移 0038_platform_solved_baselines 后补检查一次：

```powershell
docker compose exec -T web python manage.py refresh_bound_solved
docker compose exec -T web python manage.py refresh_bound_solved --apply
# 外部平台失败后显式重试；成功账号始终跳过
docker compose exec -T web python manage.py refresh_bound_solved --apply --retry-failed
```

默认预览。成功账号、正在执行的任务及已有失败检查记录会被跳过；--retry-failed 只重新检查未成功的账号。可以追加 --user-id 限定账号。实际同步结果受平台公开接口、限流、账号有效性及洛谷查询凭据影响；失败会在个人资料页提示，已有记录不清零。
