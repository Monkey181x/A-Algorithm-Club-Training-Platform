# 提交撤销后的关联状态

用户删除、管理员直接驳回或举报处理退回后，在同一事务内重算该成员该日状态。仍有有效提交时保留签到；最后一条有效提交失效时移除签到；删除操作重开补签权限，驳回操作不为总览新建提交开放免费补交权限，并按剩余有效日期撤回不再满足门槛的自然周连签奖励。

签到服务（包括独立的 `/api/currency/checkin` 接口）必须先确认相同团队、成员和日期至少有一条有效提交，再创建签到和发放奖励。它与提交创建、删除及驳回使用同一账号锁，避免检查与发奖期间提交失效。

每日奖励记录在 `CheckinRecord.reward_amount`，撤回原先实际发放的金额，避免后台配置变化导致多扣或少扣。重新提交恢复符合条件的奖励，不重复发放。连签凭证保留撤回时间，重新达标后恢复原凭证。

余额不足时，优先从未使用的背包物品，再从尚未派送成功的物品中回收，按原购买价格返还 Coins，回收到足够抵扣为止。已核销卡密、已消耗和已派送成功的物品不回收。仍不足时允许完成，剩余欠款记为负余额，后续收入抵扣。所有回收返还与奖励撤回均保留流水；回收数量还原商品库存，并从实物累计限购数量中扣除。

删除前通过 `GET /api/submissions/ID/reversal-preview?action=delete` 获取回收清单，弹窗明确显示“该操作会导致‘XX物品’被回收”。管理员驳回也使用相同审查（`action=reject`）。确认请求携带签名 `recovery_token`，有效期 5 分钟；余额、库存、派送状态或提交版本变化时必须重新确认。回收与奖励撤销、删除/驳回同一事务提交，取消确认不改变数据。

删除后，历史日期沿用已取得的补交权限，不再次扣补签券。被驳回记录的修改重交独立于补交流程：不需要补签券，保留该记录首次提交时间与原日期，恢复原日期的正常签到、每日 Coins 与符合条件的连签奖励；当天已有签到时不重复发奖。当前学期中原周已关闭的退回记录也可修改重交，归档学期仍禁止修改。仅拥有被驳回记录不会给总览新建历史提交提供免费权限；该入口仍须消耗补签券，按补交处理。

累计过题量继续由有效且截图已通过的提交与持久化 AC 证据去重计算。删除或驳回本站最后一条有效依据会减少相应题数；其他团队的有效同题、已归档证据和独立比赛 AC 不会因本次撤销而消失。热力图日期记录与累计榜单分别按各自口径刷新。

## 更新与遗留状态修复

先备份数据库，再应用迁移 `0035_signin_reward_reversal` 和 `0036_reward_inventory_recovery`。迁移从原有每日签到正向流水中记录已发金额，并增加回收凭证字段，不直接修改余额。

旧版本遗留的当前学期“没有有效提交但仍保留签到/补签完成状态”可以预览后修复：

```powershell
docker compose exec -T web python manage.py reconcile_signins
docker compose exec -T web python manage.py reconcile_signins --apply
```

可追加 `--team-id ID` 限定团队。预览会列出回收清单及修复后余额，核对后再执行 `--apply`。修复仅处理当前进行中的未归档学期，排除管理员私有测试团队，以当前学期有效提交为签到依据；不会删除提交。命令重复执行不重复扣奖励、回收物品或消耗补签券。
